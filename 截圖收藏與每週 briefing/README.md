# 截圖收藏與每週 briefing（Telegram 機器人）

在手機看到 Facebook 或其他社群內容時，截圖後「分享」給自己的 Telegram 機器人。機器人會：

1. 保存**原圖**（存在你自己的資料夾，不依賴 Telegram 暫存檔）
2. 用 AI 看圖，產生**標題、一句摘要、分類、標籤、可能的待辦**，看不清楚的地方會標示「不確定」
3. 回覆「已收藏 #編號」與整理結果；同一張圖重複傳送會友善告知已存過
4. **每週日晚上 8 點（台北時間）**寄一份繁體中文 briefing：本週數量、主要主題、最值得回看的 5–10 則、可以採取的行動，以及對應的收藏編號

只有你指定的 Telegram 使用者 ID 能操作；其他人傳訊息只會得到「沒有使用權限」。

---

## 需要準備的金鑰與設定

全部放在 `.env`（已列入 `.gitignore`，不會提交）。**不要把金鑰貼到聊天或程式碼裡。**

| 設定 | 去哪裡拿 | 費用 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Telegram 搜尋 **@BotFather** → `/newbot` → 取名 → 複製它給你的 token | 免費 |
| `ALLOWED_USER_IDS` | 你的 Telegram 數字 ID。最簡單的方法：先隨便填 `1` 啟動機器人，私訊它，它會回覆「你的 Telegram 使用者 ID：xxxx」，再把這個數字填回來重啟 | 免費 |
| `ANTHROPIC_API_KEY` | https://console.anthropic.com/ → 註冊 → 儲值（Billing）→ API Keys 建立金鑰 | **依用量付費**（見下方） |

如果暫時不想付 AI 費用，可以設定 `AI_PROVIDER=none`：機器人照樣收藏原圖、去重、可搜尋附言，但不會自動分類；之後補上金鑰、改回 `anthropic`，再輸入 `/retry` 就能一次補整理。

### 可能產生費用的環節

只有呼叫 Anthropic API 時會產生費用（Telegram 免費）：

| 動作 | 呼叫次數 | 粗估（預設模型 `claude-opus-5-5`） |
|---|---|---|
| 每收藏一張截圖 | 1 次（長截圖會切成最多 5 段，一起送一次） | 約 NT$0.5–2／張（長截圖較貴） |
| 每週 briefing | 1 次（只送文字摘要，不重送圖片） | 約 NT$1–4／週 |
| `/briefing` 預覽 | 每次 1 次 | 同上 |
| `/retry`、自動重試 | 失敗才會呼叫，每則最多自動重試 6 次 | 同截圖 |
| 拒答自動改用其他模型（`AI_FALLBACKS=default`） | 少數情況；以備援模型的價格計費 | — |

> 以上是依官方單價（Opus 5.5：輸入 US$4、輸出 US$20／百萬 token）粗估，實際以 Console 的用量頁為準。建議在 Console → Limits 設定每月上限。
> 想省錢可以在 `.env` 改 `AI_MODEL=claude-sonnet-5-5`（約一半價格）或 `claude-haiku-5-5`（便宜很多，但中文細節辨識較弱）。

另外，機器人需要一台**一直開著**的電腦（家裡的桌機、NAS、或每月約 US$5 的小型雲端主機）。如果電腦在週日 20:00 剛好關機，重新開機後 48 小時內會補寄；超過就略過那一週。

## 本機啟動

需要 Python 3.11 以上。

```bash
cd "截圖收藏與每週 briefing"
cp .env.example .env          # 用文字編輯器打開 .env 填入金鑰
python3 -m venv .venv
source .venv/bin/activate     # Windows：.venv\Scripts\activate
pip install -r requirements.txt
python -m screenshot_bot
```

看到 `啟動：AI=anthropic …` 就代表在運作了。按 `Ctrl+C` 停止。

## 用 Docker 啟動（建議長期執行用）

```bash
cd "截圖收藏與每週 briefing"
cp .env.example .env          # 填入金鑰
mkdir -p data
docker compose up -d --build
docker compose logs -f        # 看 log
```

- 資料會存在專案底下的 `data/`，重建容器也不會遺失。
- 容器以 UID 1000 執行。若在 Linux 主機上遇到 `data/` 權限錯誤：`sudo chown -R 1000:1000 data`。
- 更新程式後：`docker compose up -d --build`。

## 用手機實際測試：傳一張截圖 → 收到分類 → 收到週報

1. **找到機器人**：在 Telegram 搜尋你在 BotFather 取的機器人帳號（例如 `@my_shots_bot`），按「開始」。它會回覆使用說明。
   - 如果回覆「沒有使用權限」，把它告訴你的 ID 填進 `.env` 的 `ALLOWED_USER_IDS`，重啟後再試。
2. **傳一張截圖**：在 Facebook 截圖 → 相簿裡打開截圖 → 分享 → Telegram → 選你的機器人 →（可選）在附言寫想法或貼原文連結 → 傳送。
   - 幾秒內會先收到「📥 已收藏 #1」，接著同一則訊息會更新成「✅ 已收藏 #1」＋標題、摘要、分類、標籤、可能的待辦。
3. **試試其他功能**：
   - 同一張圖再傳一次 → 「👌 這張之前已經收藏過了」
   - 點「🏷 更正分類」按鈕改分類；點「🖼 取回原圖」拿回原檔
   - 直接打字（例如「股票」）就是搜尋；`/recent` 看最近收藏
   - 對「已收藏」那則訊息按「回覆」，貼上原文連結 → 會補進該筆收藏
4. **馬上看週報**：輸入 `/briefing`，會立刻產生「本週到目前為止」的預覽（會呼叫一次 AI）。
5. **正式週報**：週日 20:00（台北時間）會自動收到「📰 每週截圖 Briefing」。同一週只會寄一次，重啟也不會重寄。
   - 想提早驗證排程，可以暫時把 `.env` 改成 `BRIEFING_WEEKDAY` 為今天、`BRIEFING_TIME` 為幾分鐘後，重啟後等待即可（測完記得改回來）。
   - 注意：第一次啟動之前就已經結束的週期不會補寄，所以請把測試時間設在「啟動之後」。

## 指令一覽

| 指令 | 說明 |
|---|---|
| 傳圖片（照片或檔案） | 收藏並整理 |
| 直接傳文字 | 搜尋收藏（標題、摘要、標籤、截圖原文、附言、連結） |
| 回覆「已收藏」訊息 | 補充附言或原文連結 |
| `/recent [數量]` | 最近的收藏（預設 10 則，最多 30） |
| `/search 關鍵字` | 搜尋，多個關鍵字以空白分隔（全部符合才列出） |
| `/get 編號` | 取回原圖（以檔案傳送，保留原始畫質） |
| `/category 編號 [分類]` | 更正分類；不填分類會跳出按鈕。手動改過的分類不會被 AI 覆蓋 |
| `/categories` | 目前的分類清單 |
| `/retry [編號]` | 重新 AI 整理；不填編號則重試所有失敗的收藏 |
| `/delete 編號` | 刪除收藏與原圖（需按按鈕確認） |
| `/briefing` | 預覽本週 briefing（不影響正式寄送） |

## 調整分類

修改 `.env` 的 `CATEGORIES`（逗號分隔），重新啟動即可。「其他」一定會保留，AI 無法判斷或回傳不在清單裡的分類時會歸到「其他」。已經收藏的舊資料保留原本的分類；需要的話可以 `/category` 手動更正。

## 錯誤處理

| 狀況 | 機器人的行為 |
|---|---|
| AI 失敗（斷網、額度用完、金鑰錯誤、拒答） | **原圖先存好**，回覆「已收藏，但 AI 整理暫時失敗」；之後 10 分鐘、20 分鐘、40 分鐘…自動重試（最多 6 次），成功會再通知你。也可隨時 `/retry` |
| 圖片下載失敗 | 自動重試 3 次，仍失敗就請你再傳一次（不會存半個檔案） |
| 圖片太大 | Telegram 機器人最多只能下載 20 MB；會請你改用「照片」方式傳（Telegram 會自動壓縮） |
| 不是圖片／HEIC 檔 | 告知格式不支援 |
| 同一張圖重複傳 | 以檔案內容的 SHA-256 與 Telegram 檔案 ID 判斷，不重複保存並告知編號 |
| 重新壓縮過、看起來很像的圖 | 仍會保存（避免誤判漏存），但提示「和 #N 很像」，可用 `/delete` 刪掉 |
| Telegram 重送同一則訊息 | 以訊息 ID 判斷，靜默略過 |
| Telegram 傳送頻率限制 | 依 Telegram 指示的秒數等待後重送；超過 4096 字的訊息自動分段 |
| briefing 寄送失敗 | 10 分鐘後重試，最多 5 次；已寄出的週不會再寄 |
| briefing 時 AI 失敗 | 改寄「自動統計版」（依分類與標籤彙整），週報不會因此漏寄 |
| 服務在分析途中重啟 | 卡住超過 10 分鐘的項目會被重試排程接手 |

已知取捨：如果服務恰好在「正在寄送週報」的那一瞬間當機，那一週會視為已寄（寧可漏寄一次，也不重複寄）。

## 隱私與安全

- 只接受 `ALLOWED_USER_IDS` 裡的使用者，而且**只在私訊中**運作（把機器人拉進群組也不會回覆截圖內容）。
- 每位使用者只能看到、取回、刪除自己的收藏。
- 截圖會傳到 Anthropic API 做圖片理解；其他資料都留在你的 `data/`。
- 金鑰只從環境變數或 `.env` 讀取；log 不會印出 bot token。
- AI 被要求把截圖文字當作資料、不當成指令，也不能自己產生或猜測原文連結（連結只來自你的附言）。

## 程式結構

```
screenshot_bot/
├── bot.py          # Telegram 介面：收圖、指令、按鈕、定時任務、權限檢查
├── collector.py    # 收藏流程：存原圖、去重、AI 整理、失敗重試（不依賴 Telegram）
├── briefing.py     # 週報期間計算、內容產生、確保同一週只寄一次
├── formatting.py   # 繁體中文回覆文字
├── images.py       # 圖片驗證、雜湊、存檔、長截圖切段
├── db.py           # SQLite
├── config.py       # 環境變數
└── ai/
    ├── base.py               # AI 供應商介面（Analyzer）與輸出清理
    └── anthropic_provider.py # Claude 實作
```

### 換一家 AI

在 `screenshot_bot/ai/` 新增一個類別，實作 `analyze_image()` 與 `compose_briefing()` 兩個方法（參考 `anthropic_provider.py`，回傳前呼叫 `normalize_analysis()`／`normalize_briefing()` 清理），再到 `ai/__init__.py` 的 `build_analyzer()` 加一個分支、在 `config.py` 允許新的 `AI_PROVIDER` 值。

## 測試

```bash
pip install -r requirements-dev.txt
python -m pytest
```

測試不連網、不需要任何金鑰，涵蓋：重複圖片（相同內容、相同 Telegram 檔案、訊息重送、相似圖提示）、原圖存檔與欄位、AI 失敗後的狀態與自動重試、週報的時間範圍（週日 19:59／20:00、邊界含不含）、重啟後不重寄、寄送失敗重試、AI 失敗改寄統計版、權限檢查，以及用假的 Telegram 物件跑完整的「傳圖 → 已收藏 → 整理結果」流程。
